## 2. هوية المشروع والقرار المعماري

اسم المشروع: **Cyber Silicon Pro — Android Local**.

هذا التطبيق يراد له أن يعمل **محلياً على هاتف Android نفسه**، وليس واجهة تحكم لخادم Kali.

### البنية المعتمدة في هذا المستودع

- Kotlin + Jetpack Compose لواجهة Android أصلية عربية RTL.
- Room/SQLite لتخزين المقالات والمشاريع والدروس والمحادثات والمهام وسجل النشر محلياً.
- تشفير أسرار الخدمات باستخدام AES-256-GCM، مع حفظ مفاتيح التشفير في Android Keystore.
- DataStore للتفضيلات.
- WorkManager للمهام والجدولة المحلية.
- OkHttp للاتصال المباشر عبر HTTPS بواجهات الخدمات الرسمية.
- لا يعتمد هذا التطبيق على Kali أو Termux أو NetHunter أو FastAPI أو Docker أو WebView أو خادم خاص.

**لا تنقل إليه خطوات Docker/HTTPS/VPN من مشروع Hybrid السابق.**

## 6. ما الذي يوفره التطبيق حالياً؟

التقييم التفصيلي موجود في `docs/FEATURE_MIGRATION_MATRIX.md`. غالبية الوظائف نُقلت جزئياً وليست مكافئة بالكامل لنسخة سطح المكتب.

### المحتوى والذكاء الاصطناعي

- Dashboard محلي بمؤشرات المقالات والمهام والاتصالات.
- Content Studio ومحرر Markdown محليان، لكن المعاينة المتقدمة ومكتبة الوسائط غير مكتملتين.
- Gemini Article Generator وGemini Chat موجودان عبر الاتصال المباشر؛ يتطلبان مفتاح المستخدم واختباراً حياً.
- سجل محادثة Gemini محفوظ محلياً، وسياق المحادثة في التطبيق يقتصر على آخر 20 رسالة وفق مصفوفة النقل.
- أدوات SEO نُقلت إلى Kotlin.
- Course Planner يدعم إدارة المشاريع والدروس وإعادة الترتيب والربط بالمقالات، لكن التسلسل/الجدولة الآلية الكاملة ما زالت جزئية.

### النشر والاتصالات

- Blogger: Google Identity على الهاتف، اختيار مدونة الحساب، ثم نشر يدوي بعد تأكيد المستخدم. يحتاج OAuth Android مهيأً في Google Cloud. رمز الوصول قصير العمر ويُعامل كمنتهي بعد نحو 50 دقيقة؛ الجدولة الخلفية لـBlogger غير متاحة حالياً.
- Telegram: Bot Token وChat ID. يحتاج البوت إلى الوصول إلى القناة/المجموعة وصلاحية النشر؛ في الخاص يجب أن يبدأ المستخدم المحادثة مع البوت.
- Facebook: النشر للصفحات Facebook Pages باستخدام Page ID وPage Access Token وأذونات Meta المطلوبة؛ لا يوجد نشر إلى الملف الشخصي.
- GitHub: Personal Access Token واسم المستودع بصيغة `owner/repository` وBranch. يحتاج إلى صلاحية Contents read/write للمستودع.
- Gemini: مفتاح API صالح ومفعّل، واختبار توافر النماذج.
- TikTok: أزيلت الوظائف غير الرسمية مثل scraping/yt-dlp/Playwright؛ الوظائف الرسمية وحدها ممكنة بعد OAuth ومراجعة وصلاحيات المنصة.

### سجل النشر وإعادة المحاولة والجدولة

- سجل النشر يحتفظ بآخر 100 محاولة، مع الوجهة وإصدار المقال.
- إعادة المحاولة الآمنة تكون للمنصة والنسخة اللتين فشلتا، مع منع إعادة الإرسال عند وجود محاولة ناجحة مسجلة لنفس المقال/الوجهة/الإصدار.
- الجدولة المحلية متاحة لـTelegram وFacebook Pages وGitHub باستخدام WorkManager، وقد يتأخر التنفيذ بسبب قيود Android.
- Blogger مستثنى من الجدولة بسبب عمر جلسة Google وعدم وجود تجديد مضمون صالح أثناء عمل الخلفية؛ النشر اليدوي يبقى متاحاً.
- لا توجد ضمانة exactly-once في كل حالات انقطاع الاتصال؛ قد تقبل الخدمة النشر ثم يتعطل التطبيق قبل حفظ النتيجة المحلية.

### الوسائط والنسخ الاحتياطي

- معالجة دفعات حتى 30 صورة على الهاتف: ضغط JPEG، علامة مائية، تصدير ZIP عبر Android SAF، وتقرير بالصور التي فشلت.
- قص MP4 محلي باستخدام MediaExtractor/MediaMuxer دون إعادة ترميز؛ يبدأ القص عند إطار مفتاح تالٍ لوقت البداية. لا يوجد ضغط فيديو أو تحويل ترميز أو تحرير متعدد المسارات، وبعض الترميزات قد لا تدعمها حاوية MP4.
- Backup/Restore بصيغة JSON عبر SAF للمقالات والإصدارات والمشاريع والدروس والمهام وسجل النشر. مفاتيح الخدمات والمواعيد المجدولة مستثناة من النسخة الاحتياطية.
- المقالات المحلية قابلة للقراءة والتحرير دون إنترنت.

## 7. المشكلة الأخيرة التي توقفنا عندها

قال المستخدم:

> جربت الاصدار فيه مشكلة الربط مع المنصات وخصوصا بلوجر

المساعد راجع إصدار v1.0.1 وذكر أن APK موقّع بالبصمة الدائمة الموثقة، ولذلك لا يبدو اختلاف التوقيع هو سبب المشكلة. كما لاحظ أن رسائل الخطأ من بعض المنصات كانت عامة وتخفي السبب الحقيقي.

تم فتح PR #15 لتحسين التشخيص والإرشادات. التغييرات المعلنة فيه:

1. إظهار تفاصيل الخطأ التي ترجعها Gemini وBlogger وTelegram وMeta وGitHub مع رمز HTTP، دون كشف بيانات الاعتماد.
2. توضيح أخطاء DNS وtimeout وTLS والاتصال.
3. Telegram: فحص Bot Token باستخدام `getMe` ثم فحص Chat ID/الوجهة باستخدام `getChat`، وحفظ Chat ID مشفراً واستخدامه افتراضياً في محرر المقال.
4. GitHub: فحص الوصول إلى المستودع المحدد، لا مجرد فحص صلاحية الرمز على `/user`.
5. تنظيف/توحيد القيم الملصوقة قبل اختبارها وحفظها.
6. إرشادات Blogger داخل التطبيق تتضمن تفعيل Blogger API v3، إعداد Google Auth Platform، OAuth Client من نوع Android، اسم الحزمة، وبصمة Release SHA-1، مع زر لنسخ البصمة.
7. توضيح متطلبات الاتصال بكل منصة.

**الحالة الحالية:** PR #15 مفتوح وغير مدمج رغم نجاح CI. لا يوجد دليل على إصدار APK جديد يتضمنه، ولا على اختبار حي للمنصات.

المساعد طلب من المستخدم آخر مرة معلومة واحدة:

**ما الرسالة الدقيقة التي تظهر عند الضغط على «تسجيل الدخول إلى Google» في قسم Blogger؟**

المطلوب من المستخدم في المتابعة: إرسال صورة للرسالة أو كتابة نص الخطأ، مع إخفاء أي Token أو كلمة مرور أو بيانات سرية. لا تفترض سبباً بعينه قبل معرفة الخطأ.

## 8. متطلبات Google Blogger OAuth الموثقة

وفق README وPR #15:

1. في Google Cloud اختر المشروع المقصود وفعّل Blogger API v3.
2. أكمل إعداد Google Auth Platform وشاشة الموافقة والجمهور.
3. أنشئ OAuth Client من نوع **Android**، وليس Web.
4. استخدم اسم الحزمة `com.cybersilicon.pro` وبصمة SHA-1 التي تطابق APK المثبت فعلياً.
5. إذا كان المشروع في وضع Testing فأضف حساب Google المستخدم إلى Test users.
6. يجب أن يكون الحساب مالكاً للمدونة أو يملك صلاحية النشر فيها.
7. افتح شاشة الاتصالات في التطبيق واضغط «تسجيل الدخول إلى Google»، ثم وافق على نطاق Blogger واختر المدونة.
8. لا تطلب Client Secret ولا تضعه في APK؛ لا يحتاج هذا التطبيق المحلي إلى وسيط خادم أو Web OAuth Client حسب تصميم المستودع.
9. رمز الوصول مشفّر محلياً، لكنه قصير العمر؛ قد يتطلب تسجيل الدخول مجدداً بعد نحو 50 دقيقة.

هذه خطوات إعداد، وليست دليلاً على أن تكامل Blogger نجح بالفعل. الاختبار الحقيقي يكون بتسجيل الدخول واختيار المدونة ثم نشر مقال تجريبي بعد موافقة المستخدم والتحقق من ظهوره.
